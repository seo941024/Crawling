# 오카시에리 프로젝트 정리

여러 일본 과자 직구 쇼핑몰의 상품과 가격을 한곳에서 검색하고 비교한 뒤, 원하는 쇼핑몰의 상품 페이지로 이동하게 하는 사이트입니다.
이름은 お菓子(오카시, 과자) + おかえり(오카에리, "어서 와")입니다.

이 문서는 지금까지 한 일을 한 번에 읽도록 정리한 것입니다. 선택마다의 이유는 `DECISIONS.md`에 더 자세히 있습니다. 발표 자료 초안은 `오카시에리_포트폴리오.pptx`(43장, 슬라이드 노트에 발표 대본, 화면 캡처는 `ppt_images/`)입니다.

## 2. 만든 과정

1. **수집**: 쇼핑몰마다 구조를 직접 분석해서 이름, 정가, 할인가, 이미지, 상품 링크를 모았습니다.
2. **정리**: 가격 문자열을 숫자로 바꾸고, 중복과 과자가 아닌 상품(화장품, 양말, 파우치)을 걸러서 SQLite에 넣었습니다.
3. **분류**: 사이트마다 분류가 달라서, 이름의 키워드로 직접 만든 9개 분류에 자동으로 넣었습니다.
4. **서비스**: Flask 서버와 순수 HTML/CSS/JS 화면으로 검색 사이트를 만들었습니다.
5. **확인**: robots.txt와 이용약관을 읽고 재팬푸드몰을 제외했습니다.

### 쇼핑몰별 수집

| 쇼핑몰 | 정적/동적 | 방식 | 특이사항 |
|---|---|---|---|
| 코코재팬 | 정적 | `requests` + `BeautifulSoup`, 더보기는 AJAX 주소를 직접 호출 | 상단 BEST 캐러셀이 같은 클래스를 써서 걸러냄 |
| 엔핍 | **동적** | **Selenium**으로 렌더링 후 파싱 | 카드 첫 `<img>`가 BEST 뱃지인 상품이 약 140개라, 상품 페이지의 `og:image`로 교체 |
| 이로이로도쿄 | 정적 | `requests` + `BeautifulSoup`, `/page/N/` 반복 | 이미지가 지연 로딩이라 `data-src`를 읽음. 마지막 페이지를 넘기면 404가 아니라 메인으로 리다이렉트됨 |
| 재팬푸드몰 | 정적 | 수집은 했음 | robots.txt가 전체 금지라 **서비스에서 제외** |
| 구루메상 | 정적 | 수집은 했음 | 더미 상품과 스팸이 많은 사실상 중단 사이트라 제외 |

사이트마다 먼저 "정적인가 동적인가"를 확인했습니다. 원본 HTML에 상품이 있으면 `requests`, 없으면 Selenium을 썼습니다. 정적 사이트에 Selenium을 쓰면 느리고, 동적 사이트에 `requests`를 쓰면 빈 데이터가 오기 때문입니다.

## 3. 핵심 판단 (왜 그렇게 했나)

- **SQLite**: 서버 설치가 필요 없고 DB가 파일 하나입니다. 상품 수천 개, 읽기 위주라 충분합니다. 사용자가 많아지면 PostgreSQL로 옮겨야 합니다.
- **Flask + 순수 JS**: 서비스 구조를 직접 설계해 볼 수 있고 빌드 도구가 필요 없습니다.
- **초성 칼럼을 미리 저장**: 검색할 때마다 계산하지 않고 저장 시 한 번만 계산합니다.
- **분류는 "이름에서 가장 뒤에 나오는 종류 단어"**: 한국어 상품명은 종류가 끝에 오는 경우가 많습니다("초콜릿 커버 비스킷"은 비스킷). "녹차맛" 같은 맛 표현은 먼저 지웁니다. 틀린 분류가 보이면 `categorize.py`의 직접 분류 목록에 넣으면 규칙보다 우선합니다.
- **같은 상품 묶기와 용량당 가격은 하지 않음**: 사이트마다 이름 표기가 달라 틀리게 묶으면 잘못된 비교가 됩니다. 대신 가격순 정렬로 쇼핑몰별 가격을 비교합니다.
- **필터는 사이드바에만**: 상단 메뉴에 같은 필터를 두면 중복이라 뺐습니다.
- **페이지 번호 방식**: 상품이 3천 개가 넘어 "더보기"는 마지막 페이지까지 가기 어렵습니다.
- **검색 보안**: 검색어는 파라미터 바인딩과 `LIKE` 이스케이프, 정렬 기준은 허용 목록, DB는 읽기 전용, 카드는 `textContent`로 그립니다.

## 4. 실수와 고친 것

| 문제 | 원인 | 조치 |
|---|---|---|
| 엔핍 이미지 141개가 BEST 뱃지 그림 | 카드의 첫 `<img>`를 집음 | 저장된 데이터를 눈으로 확인하다 발견, 상품 페이지의 대표 이미지로 교체 |
| 이로이로도쿄 크롤러가 198페이지까지 헛돌고 메인 페이지 상품 65개가 섞임 | 마지막 페이지를 넘기면 404가 아니라 메인으로 리다이렉트되는 것을 놓침 | 리다이렉트를 감지해 멈추고, "새 상품이 없으면 종료" 조건 추가. DB에는 영향 없었음 |
| 복구한 엔핍 이미지가 다른 상품 이미지로 연결될 뻔함 | DB 번호가 바뀌었는데 같은 번호의 파일이 있으면 건너뛰도록 만듦 | 복구 이미지를 상품 주소 기준 캐시(`image_cache/`)로 바꿈 |
| 이름이 같은 상품 8개의 이미지가 서로 덮어써짐 | 수집할 때 이미지 파일을 상품명으로 저장함 | DB를 만들 때 이름이 같은데 사진이 다른 상품은 자기 이미지 주소로 다시 받음 |
| 초성 예시 "ㅋㅅㅋ = 킷캣" | "킷"의 ㅅ은 받침이라 초성이 아님. 킷캣의 초성은 ㅋㅋ | 화면과 문서의 예시를 모두 수정 |
| 분류 오류("쇼콜라"의 콜라, "청시소 다진"의 소다) | 띄어쓰기를 지운 뒤 다른 단어에 낀 글자까지 일치 | 먼저 다른 단어로 바꾸는 처리, "기타" 214개를 25개 이하로 줄임 |
| 상단 메뉴가 사이드바와 중복 | 메뉴를 채우려고 필터를 복사해 넣음 | 상단 메뉴는 홈과 소개만 남김 |
| 소개 문구가 "싼 곳으로 이동"이라고 잘못 설명 | 서비스는 사용자가 원하는 곳으로 이동시키는 것 | 문구 수정, 말투를 "~합니다"로 통일 |
| robots.txt를 크롤링 후에 확인 | 순서 실수 | 재팬푸드몰 제외, 새 사이트는 1단계에서 확인 |

## 5. 아직 남은 것과 알아둘 것

- **공개 배포는 신중하게**: 약관이 정보의 복제와 제공을 제한합니다. 내 컴퓨터 시연과 화면 캡처는 부담이 적지만, 인터넷에 공개하려면 각 쇼핑몰에 허락을 받는 쪽이 안전합니다.
- **홈 화면**: 지금은 홈과 목록이 같은 화면입니다. "홈을 누르면 바로 목록이 뜨는 게 어색하다"는 의견이 있어서, 어떤 점이 거슬리는지 정해서 고쳐야 합니다.
- **수집 자동화**: 지금은 수동입니다. 정해진 시간에 자동으로 돌게 하려면 스케줄러가 필요합니다.
- **이로이로도쿄 분류**: 규칙으로 자동 분류했고 눈으로 샘플 검사는 하지 않았습니다.
- **비타민 구미**(UHA 구미서플리 등)는 사탕·젤리에 들어 있습니다. 영양제로 볼지 과자로 볼지 정하지 않았습니다.
- **코코마이**(엔화 판매)는 환율과 배송비 기준을 정해야 해서 보류했습니다.
- **이미지가 없는 상품이 2개**(엔핍) 있습니다. 상품 페이지에 대표 이미지가 없어서 화면에 "이미지 없음"으로 표시됩니다.
- **가격은 수집 시점의 값**입니다. 실제 가격과 재고는 다를 수 있습니다.
- `all_crawling.ipynb`에는 재팬푸드몰 수집이 들어 있으니 **다시 돌리지 마세요.**
- 재팬푸드몰 원본 수집 파일(`JapanFoodMall_Product_Information.csv`, `JfmallImages/`)은 지우지 않고 로컬에 남겨 두었습니다. 지우고 싶으면 폴더를 직접 삭제하면 됩니다.

## 6. 실행 방법

`Crawling` 환경(anaconda)에서 실행합니다.

```bash
cd okashieri
python app.py          # http://127.0.0.1:5000 에서 확인 (개발용 서버)
```

DB를 다시 만들려면 (수집 CSV를 바꾼 뒤):

```bash
python build_db.py     # 처음엔 엔핍 뱃지 이미지를 다시 받느라 몇 분 걸리고, 이후엔 image_cache를 씁니다
```

이로이로도쿄만 다시 수집하려면 (`웹스크래핑` 폴더에서, 약 30분):

```bash
python crawl_iroiro.py
```

필요한 패키지는 `requirements.txt`에 있습니다(`pip install -r requirements.txt`).

```
   ├─ 프로젝트_정리.md    이 문서
   └─ requirements.txt
```
