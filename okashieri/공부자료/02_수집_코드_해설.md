# 02. 수집 코드 해설

수집 스크립트 3개(`crawl_coco.py`, `crawl_nppip.py`, `crawl_iroiro.py`)는 구조가 거의 같습니다.
먼저 공통 뼈대를 이해하고, 사이트별 차이를 봅니다. (원래는 사이트별 주피터 노트북이었다가, 서버에서 주기적으로 돌리려고 스크립트로 옮겼습니다.)

## 1. 공통 뼈대

```
1. 임시 파일(.tmp)에 CSV를 쓰기 시작
2. 페이지 번호 1부터 반복:
     a. 해당 페이지 요청
     b. 상품 카드 찾기
     c. 각 카드에서 이름·정가·할인가·이미지·링크 추출
     d. "새 상품"만 골라냄 (이미 본 상품 제외)
     e. 새 상품이 없으면 종료
     f. 이미지 다운로드, CSV에 한 줄씩 기록
3. 끝까지 성공하면 .tmp → 진짜 CSV로 교체
```

### 왜 임시 파일에 쓰고 마지막에 교체하나 (`os.replace`)
수집 도중 사이트 장애나 네트워크 오류로 중단되면, 진짜 CSV에 쓰고 있었다면 **반쪽짜리 CSV**가 남습니다.
임시 파일에 쓰고 끝까지 성공했을 때만 교체하므로, **실패해도 이전의 온전한 CSV가 유지**됩니다.
```python
tmp_path = csv_path + ".tmp"
...
if not seen:
    raise SystemExit("수집된 상품이 0개라서 기존 CSV를 유지합니다.")
os.replace(tmp_path, csv_path)
```

### `seen` 집합과 종료 조건
```python
new = [it for it in items if it[4] not in seen]   # it[4] = 상품 링크
if not new:
    break      # 상품이 없거나 같은 상품만 반복되면 마지막 페이지
```
- 집합(set)은 "이미 본 것인가"를 빠르게 확인합니다.
- 엔핍은 링크에 정렬 조건이 붙어 주소가 달라질 수 있어서 `item_key()`가 상품 번호(`it_id`)만 뽑아 비교합니다.

### 공통 함수
```python
def safe_filename(name):
    return re.sub(r'[\\/:*?"<>|]', '_', name)    # 윈도우 파일명 금지 문자를 _로
```
`HEADER = ["제품명", "정가", "할인가", "이미지URL", "상품링크"]` — CSV의 열 이름. (이로이로도쿄만 맨 앞에 "카테고리")

### 이미지 다운로드
```python
img_path = os.path.join(img_dir, safe_filename(name) + ".jpg")
if not os.path.isfile(img_path):                       # 이미 있으면 건너뜀
    r = requests.get(imgurl, headers=HDR, timeout=30)
    time.sleep(random.randint(1, 2))
    with open(img_path, "wb") as out:                  # wb = 바이너리 쓰기
        out.write(r.content)                           # content = 바이트
```
- 텍스트는 `res.text`, 이미지는 `r.content`(바이트).
- **알려진 약점**: 파일 이름을 상품명으로 저장하므로 이름이 같은 다른 상품은 덮어써집니다. 이 문제는 `build_db.py`에서 보정합니다(04번 문서).

### 명령줄 옵션 (시험 실행용)
```
python crawl_coco.py --max-pages 2        # 2페이지만 (시험)
python crawl_coco.py --out-dir D:\data    # 저장 위치 지정
```
`argparse`로 받습니다. 전체를 돌리면 수십 분~몇 시간이라, 코드를 고친 뒤에는 짧게 시험해 봅니다.

## 2. 코코재팬 — `crawl_coco.py` (정적 + AJAX 더보기)

```python
FIRST_PAGE = HOME + "/shop/list.php?ca_id=4010"
AJAX_PAGE  = HOME + "/mobile/shop/list_more_ajax.php?ca_id=4010&sort=&sortdr=&page={page}"
...
url = FIRST_PAGE if page == 1 else AJAX_PAGE.format(page=page)
```
- 1페이지는 일반 페이지, 2페이지부터는 "더보기" 버튼이 부르는 AJAX 주소.
- `ca_id=4010`: 일본 과자 카테고리 하나만 수집.

### 상품 추출
```python
cards = soup.find_all('li', attrs={'class': 'sct_li'})
cards = [p for p in cards if p.find('span', attrs={'class': 'best_icon'}) is None]
```
상단의 **BEST 캐러셀**이 상품 목록과 같은 class(`sct_li`)를 써서, 그대로 두면 같은 상품이 중복으로 잡힙니다.
BEST 표시(`best_icon`)가 있는 것은 제외합니다.

```python
name  = product.find('div', attrs={'class': 'sct_txt'}).get_text().strip()
price = product.find('span', attrs={'class': 'coco2-was'})         # 정가(취소선)
price = price.get_text().strip() if price else 'NoDiscount'         # 없으면 'NoDiscount'
dis_price = product.find('span', attrs={'class': 'coco2-now'})      # 할인가
```
할인이 없는 상품은 정가 태그가 없습니다(`None`). 그대로 `.get_text()`를 부르면 오류이므로 `if price else`로 막고, 대신 'NoDiscount' 문자열을 넣습니다. DB로 옮길 때 숫자로 처리합니다(04번).

```python
link = urljoin(HOME, product.find('a').get('href'))
```
`href`가 `/shop/item.php?...`처럼 상대경로일 수 있어서 `urljoin`으로 완전한 주소를 만듭니다.

### 종료
`res.status_code != 200`이거나 새 상품이 없으면 종료. 실제 마지막은 88페이지(2026-10 기준, `HARD_LIMIT`의 주석).

### 이 사이트에서 겪은 문제
1. BEST 중복 → `best_icon` 필터
2. 페이지 수 고정(8) → 192건만 수집 → 종료 조건으로 교체 → 2,092건
3. 상품명에 줄바꿈 → 저장 시 오류 → `.strip()`

## 3. 엔핍 — `crawl_nppip.py` (동적 + Selenium)

```python
def make_driver():
    opt = Options()
    opt.add_argument("--headless=new")          # 화면 없이
    opt.add_argument("--no-sandbox")            # 리눅스 서버에서 필요
    opt.add_argument("--disable-dev-shm-usage") # 서버의 작은 공유 메모리 문제 회피
    opt.add_argument("--window-size=1400,1000")
    opt.add_argument("--lang=ko-KR")
    return webdriver.Chrome(service=Service(ChromeDriverManager().install()), options=opt)
```
`--no-sandbox`, `--disable-dev-shm-usage`는 GitHub Actions 같은 리눅스 서버에서 크롬이 죽지 않게 하는 흔한 설정입니다.

```python
driver.get(url_page)
time.sleep(3)                                     # 자바스크립트가 상품을 그릴 시간
soup = BeautifulSoup(driver.page_source, "lxml")  # 그려진 뒤의 HTML
cards = soup.find_all('div', attrs={'class': 'item-row'})
```
- 수집 당시 기록: `requests`로 `item-row` 0개, Selenium으로 20개. (2026-10 재확인에서는 requests도 20개 — 01번 문서 참고. 코드는 Selenium 경로를 그대로 유지)
- `try ... finally: driver.quit()`: 오류가 나도 브라우저 프로세스를 반드시 종료.

### 이 사이트에서 겪은 문제
- **배지 이미지 약 140개**: 카드 안의 첫 `<img>`가 상품 사진이 아니라 BEST 배지인 상품이 있었음. 저장된 이미지를 눈으로 보다가 발견.
  `build_db.py`가 `/data/badge/`가 들어간 이미지 주소를 감지해서, 상품 페이지의 `og:image`(대표 이미지)로 다시 받습니다(04번).
- 66페이지 전체에 30분 이상: 페이지마다 3초 대기 + 이미지 다운로드 지연 때문.
- 종료: 66페이지에서 새 상품이 없어 종료.

## 4. 이로이로도쿄 — `crawl_iroiro.py` (정적 + 경로형 + 카테고리 4개)

```python
CATEGORIES = {
    "쿠키스낵과자": "쿠키-스낵-과자",
    "초콜릿사탕젤리껌": "초콜릿-사탕-젤리-껌",
    "곤약젤리": "곤약젤리-무료배송-식품",
    "견과건과안주": "견과-건과-안주",
}
url = ROOT + slug + "/" + ("" if page == 1 else f"page/{page}/")
```
통합 목록이 없어 카테고리 4개를 각각 끝까지 돕니다. 카테고리 이름이 CSV 첫 열이 되고, 나중에 분류의 참고 정보(`SOURCE_FALLBACK`)로 쓰입니다.

### 마지막 페이지 감지 — 리다이렉트
```python
if unquote(res.url).rstrip("/") != unquote(url).rstrip("/"):
    print(cat_name, f"{page}페이지부터 리다이렉트 -> 카테고리 끝")
    break
```
- 보통은 없는 페이지에 404가 오는데, 이 사이트는 **메인 페이지로 이동(리다이렉트)** 시킵니다. 상태코드는 200이라 눈치채기 어렵습니다.
- `res.url`은 이동이 끝난 뒤의 최종 주소입니다. 요청한 주소와 다르면 이동당한 것 → 끝.
- `unquote`: 한글 주소가 `%ED%95...`로 인코딩되어 있어, 풀어서 비교.
- 이것을 몰랐을 때는 198페이지까지 같은 메인 페이지를 반복 수집했습니다.

### 가격: 할인 상품
```python
del_tag = card.select_one("span.price del .woocommerce-Price-amount")   # 정가 (취소선)
ins_tag = card.select_one("span.price ins .woocommerce-Price-amount")   # 할인가
```
워드프레스 쇼핑몰(WooCommerce)은 할인 상품에 `<del>`(정가)·`<ins>`(판매가)를 함께 씁니다.
```python
def won(text):
    digits = re.sub(r'[^\d]', '', text or '')
    return f"{int(digits):,}원" if digits else None
```
숫자만 뽑아서 "1,900원" 형식으로 통일.

### 품절 제외
```python
cards = [c for c in cards if "outofstock" not in c.get("class", [])]
```

`load_old_rows()`로 이전 CSV를 읽어, 이미 받은 상품의 이미지는 다시 받지 않습니다(매주 수집 시간 절약).
