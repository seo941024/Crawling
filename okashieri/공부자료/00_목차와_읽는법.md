# 오카시에리 프로젝트 공부 자료

이 자료는 **우리가 이 프로젝트에서 실제로 한 일**을 처음부터 끝까지 이해하기 위한 것입니다.
크롤링을 몰라도 읽을 수 있게, 개념 → 우리 코드 → 왜 그렇게 했는지 → 겪은 문제 순서로 씁니다.
코드는 프로젝트에 있는 실제 파일에서 가져왔고, 파일 이름과 위치를 함께 적었습니다.

## 프로젝트 한 줄 설명
일본 과자 대행구매 쇼핑몰 여러 곳의 상품·가격을 모아서(크롤링), 정리해서 DB에 넣고(SQLite),
한 곳에서 검색·비교할 수 있게(Flask 웹사이트) 만든 것. 이름 오카시에리는 오카시(과자)와 오카에리(어서 와)를 합친 말.

## 전체 흐름 (이 그림을 머리에 넣고 시작)

```
[쇼핑몰 웹사이트]
      │  ① 수집: crawl_coco.py / crawl_nppip.py / crawl_iroiro.py
      ▼
[CSV 파일 + 이미지 폴더]      ← "원본". 수집한 그대로 저장
      │  ② 정제·분류·저장: okashieri/build_db.py + categorize.py
      ▼
[okashieri.db (SQLite)]        ← 가격이 숫자로, 중복 제거, 분류 붙은 "서비스용 데이터"
      │  ③ 조회: okashieri/app.py (Flask)  → JSON
      ▼
[브라우저 화면: app.js]       ← 검색·필터·정렬·페이지, 상품 클릭 시 쇼핑몰로 이동

      ④ 자동화: .github/workflows/weekly-crawl.yml (매주 ①을 다시 실행)
```

## 숫자 (코드와 DB에서 확인한 값)
- 원본 CSV 수집량: 코코재팬 2,092 / 이로이로도쿄 2,181 / 엔핍 1,318 / 재팬푸드몰 703 / 구루메상 607 = 6,901건
- 서비스 DB: 5,585건 (코코재팬 2,092 + 엔핍 1,312 + 이로이로도쿄 2,181). 엔핍이 6건 줄어든 것은 중복·제외 때문.
- 서비스에서 제외한 2곳: 재팬푸드몰(robots.txt 전면 금지), 구루메상(운영 중단·더미 상품)

## 파일 구성
| 번호 | 파일 | 내용 |
|---|---|---|
| 01 | 웹과_크롤링_기초 | HTTP 요청/응답, HTML, 정적·동적, 파싱, 상태코드 |
| 02 | 수집_코드_해설 | 사이트 3곳의 수집 코드를 줄 단위로 |
| 03 | 수집_허용범위 | robots.txt, 약관, 제외한 사이트, 코코재팬 403 건 |
| 04 | 정제_분류_DB | CSV→DB 변환, 분류 규칙, SQL |
| 05 | 서비스_Flask_JS | 서버 코드, API, 화면 코드, 시작 화면 |
| 06 | 자동화 | GitHub Actions 워크플로 해설 |
| 07 | 겪은_문제_기록 | 문제 → 점검 방법 → 결과 → 해결 |
| 08 | 예상질문 | 물어볼 만한 질문과 답 |
