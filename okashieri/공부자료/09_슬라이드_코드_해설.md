# 슬라이드 코드 해설 (최종_최종_최종 기준)

슬라이드에 사진으로 들어간 코드를 **한 줄씩** 설명합니다. 줄 번호는 실제 파일의 줄 번호와 같습니다.
각 코드마다 순서는 같습니다.

1. **이 코드가 하는 일** (한 문장)
2. **코드와 한 줄씩 설명**
3. **앞뒤 흐름**: 이 줄들 앞뒤에서 무슨 일이 일어나는지
4. **질문이 나오면**

모르는 파이썬 문법은 각 장 끝의 **문법 메모**에 따로 모았습니다.

| 슬라이드 | 코드 | 파일 |
|---|---|---|
| 6장 수집 도구 선택 | 정적 수집, 동적 수집 | `crawl_coco.py`, `crawl_nppip.py` |
| 7장 수집 허용 범위 | robots.txt 확인 | `check_robots.py`, `.github/workflows/weekly-crawl.yml` |
| 8장 종료 조건·차단 대응 | 종료 조건, 파일 교체, 리다이렉트, 403 기록 | `crawl_coco.py`, `crawl_iroiro.py`, `check_robots.py` |

## 6장 수집 도구 선택

### ① 정적 사이트: `crawl_coco.py` 75~77줄

**이 코드가 하는 일**: requests로 받은 HTML에서 상품 카드를 전부 찾아 꺼낸다.

```python
75  soup = BeautifulSoup(res.text, "lxml")
76  cards = soup.find_all('li', attrs={'class': 'sct_li'})
77  cards = [p for p in cards if p.find('span', attrs={'class': 'best_icon'}) is None]
```

| 줄 | 뜻 |
|---|---|
| 75 | `res.text`는 requests가 받아 온 HTML 글자 덩어리입니다. 이걸 BeautifulSoup에 넣어 **태그 구조로 읽을 수 있는 상태**(`soup`)로 만듭니다. `"lxml"`은 HTML을 읽는 엔진 이름입니다. |
| 76 | `soup`에서 `<li class="sct_li">` 태그를 **전부** 찾습니다. 하나가 상품 카드 하나입니다. **F12 캡처의 첫 번째 빨간 박스가 바로 이 태그입니다.** |
| 77 | 찾은 카드 중 `best_icon`(BEST 표시)이 **없는** 것만 남깁니다. 코코재팬은 페이지 위쪽 BEST 상품 띠에 같은 상품이 또 나와서, 이걸 빼야 중복이 안 생깁니다. |

**앞뒤 흐름**
- 바로 앞(69~70줄): 1페이지는 일반 주소, 2페이지부터는 '더보기' 버튼이 부르는 숨은 주소(AJAX)로 요청합니다.
  ```python
  69  url = FIRST_PAGE if page == 1 else AJAX_PAGE.format(page=page)
  70  res = get_with_retry(url, headers=HDR, timeout=30)
  ```
- 바로 뒤(78줄): 카드마다 `parse_card`로 상품명·가격·이미지·링크를 꺼냅니다. `parse_card`(44~52줄)가 찾는 클래스가 F12 캡처의 나머지 빨간 박스입니다.
  ```python
  45  name = product.find('div', attrs={'class': 'sct_txt'}).get_text().strip()   # 상품명
  46  price = product.find('span', attrs={'class': 'coco2-was'})                   # 정가
  48  dis_price = product.find('span', attrs={'class': 'coco2-now'})               # 할인가
  ```
  - `find`는 **첫 번째 하나**, `find_all`은 **전부**를 찾습니다.
  - `.get_text()`는 태그 안의 글자만 꺼내고, `.strip()`은 앞뒤 공백을 지웁니다.
  - 47줄 `price.get_text().strip() if price else 'NoDiscount'`: 정가 태그가 없으면(할인을 안 하는 상품) `'NoDiscount'`라고 적어 둡니다.

**질문이 나오면**
- **클래스 이름은 어떻게 알았나요?** 개발자도구(F12)로 상품 카드 하나를 열어 봤습니다. 6장 왼쪽 아래 캡처가 그 화면입니다.
- **F12 캡처에는 `sct_li sct_clear`인데 코드는 `sct_li`만 찾아요.** 태그에는 클래스를 여러 개 붙일 수 있고, BeautifulSoup은 그중 하나만 맞아도 찾습니다.

### ② 동적 사이트: `crawl_nppip.py` 76~79줄

**이 코드가 하는 일**: 실제 크롬을 띄워 페이지를 열고, JavaScript가 상품을 채울 때까지 기다린 뒤, 완성된 HTML에서 상품 카드를 찾는다.

```python
76  driver.get(url_page)
77  time.sleep(3)  # 자바스크립트 렌더링 대기
78  soup = BeautifulSoup(driver.page_source, "lxml")
79  cards = soup.find_all('div', attrs={'class': 'item-row'})
```

| 줄 | 뜻 |
|---|---|
| 76 | `driver`는 Selenium이 조종하는 크롬 브라우저입니다. `get`은 "이 주소를 열어"라는 뜻입니다. |
| 77 | 3초 기다립니다. 그동안 브라우저가 JavaScript를 실행해 상품을 화면에 채웁니다(렌더링). |
| 78 | `driver.page_source`는 **렌더링이 끝난 뒤의 HTML**입니다. 정적 사이트의 `res.text` 자리에 이게 들어간 것이 핵심 차이입니다. |
| 79 | 엔핍은 상품 카드 하나가 `<div class="item-row">`입니다. |

**정적과 동적 비교 (이 장의 요점)**

| | 정적 (코코재팬) | 동적 (엔핍) |
|---|---|---|
| HTML을 얻는 방법 | `requests.get(url)` → `res.text` | `driver.get(url)` → 3초 대기 → `driver.page_source` |
| 브라우저 | 안 띄움 (빠름) | 크롬을 띄움 (느림) |
| 분석 | BeautifulSoup | BeautifulSoup (같음) |

HTML을 **얻는 방법만 다르고**, 얻은 뒤 분석하는 방법은 같습니다.

**앞뒤 흐름**
- 크롬은 33~40줄 `make_driver()`에서 만듭니다. `--headless=new`는 **화면 없이** 크롬을 띄우는 옵션입니다. GitHub 서버에는 모니터가 없어서 필요합니다.
- 97~98줄 `finally: driver.quit()`: 중간에 오류가 나도 크롬은 꼭 닫습니다. 안 닫으면 크롬이 계속 떠 있습니다.

**질문이 나오면**
- **3초는 왜 3초인가요?** ★ 지수 답 정하기. (더 나은 방법: `WebDriverWait`로 상품 요소가 나타날 때까지만 기다리기)

### 문법 메모
- **리스트 컴프리헨션** `[p for p in cards if 조건]`: "cards에서 조건에 맞는 p만 모은 새 리스트". for문을 한 줄로 쓴 것입니다.
- **`A if 조건 else B`**: 조건이 참이면 A, 아니면 B.
- **`attrs={'class': 'sct_li'}`**: "class 속성이 sct_li인 것". `class`는 파이썬 예약어라서 이렇게 사전으로 넘깁니다.

## 7장 수집 허용 범위 확인: `check_robots.py`

**이 코드가 하는 일**: 사이트의 robots.txt를 읽고, 우리가 수집할 주소마다 허용되는지 판단한다. 하나라도 금지면 수집을 멈춘다.

슬라이드 사진은 42·44·55줄입니다. 앞뒤를 함께 봐야 이해가 됩니다.

```python
37  res = requests.get(robots_url, timeout=20, headers={"User-Agent": "Mozilla/5.0"})
42  parser = rp.RobotFileParser()
43  if res.status_code == 200:
44      parser.parse(res.text.splitlines())
45  elif res.status_code in (404, 410):
46      parser.parse([])  # robots.txt가 없으면 제한이 없는 것으로 본다
...
54  for u in urls:
55      ok = parser.can_fetch(UA, u)
56      print(("[허용] " if ok else "[금지] ") + label, u)
57      if not ok:
58          bad += 1
59  if bad:
60      print(f"\n허용되지 않은 항목 {bad}개: 수집을 중단합니다.")
61      sys.exit(1)
```

| 줄 | 뜻 |
|---|---|
| 37 | `https://사이트/robots.txt`를 받아 옵니다. |
| 42 | 파이썬 기본 기능 `urllib.robotparser`의 robots.txt 해석기를 만듭니다. (`rp`는 7줄에서 붙인 줄임 이름) |
| 43~44 | 정상(200)으로 받았으면 글자를 줄 단위로 나눠(`splitlines`) 해석기에 넣습니다. 이것이 **파싱**입니다. |
| 45~46 | robots.txt가 없으면(404) 제한이 없다고 봅니다. |
| 54~55 | 수집할 주소(`urls`)를 하나씩 `can_fetch`에 물어봅니다. 허용이면 `True`, 금지면 `False`. `UA = "*"`는 "모든 크롤러 기준"이라는 뜻입니다. |
| 57~58 | 금지된 주소 개수를 셉니다. |
| 59~61 | 하나라도 있으면 `sys.exit(1)`로 **실패 상태로 종료**합니다. |

**`sys.exit(1)`이 왜 수집을 멈추나** (`weekly-crawl.yml` 35~38줄)
```yaml
- name: 엔핍 (robots.txt 확인 후 Selenium 수집)
  run: |
    python check_robots.py 엔핍
    python crawl_nppip.py
```
- GitHub Actions는 앞 명령이 실패(0이 아닌 값으로 종료)하면 **다음 줄을 실행하지 않습니다.**
- 그래서 `check_robots.py`가 `exit(1)`로 끝나면 `crawl_nppip.py`는 아예 돌지 않습니다. 이것이 슬라이드의 "비허용 시 수집 중단"입니다.

**질문이 나오면**
- **재팬푸드몰은 이 코드에 없는데요?** 이미 금지를 확인해서 서비스에서 뺐기 때문에, 자동 수집 대상(`TARGETS`, 13~24줄)에 넣지 않았습니다.

## 8장 수집 종료 조건과 접근 차단 대응

### ① 코코재팬: 새 상품이 없으면 종료, 성공했을 때만 파일 교체 (`crawl_coco.py`)

**이 코드가 하는 일**: 새 상품이 하나도 안 나오면 마지막 페이지로 보고 멈춘다. 끝까지 성공했을 때만 기존 CSV를 새 CSV로 바꾼다.

```python
59  tmp_path = csv_path + ".tmp"
61  seen = set()
62  with open(tmp_path, "w", encoding="utf-8-sig", newline="") as f:
...
79      new = [it for it in items if it[4] not in seen]
81      if not new:
82          break  # 상품이 없거나 같은 상품만 반복되면 마지막 페이지다
...
96  if not seen:
97      raise SystemExit("수집된 상품이 0개라서 기존 CSV를 유지합니다.")
98  os.replace(tmp_path, csv_path)
```

| 줄 | 뜻 |
|---|---|
| 59 | 결과를 바로 진짜 CSV에 쓰지 않고, 이름 뒤에 `.tmp`를 붙인 **임시 파일**에 씁니다. |
| 61 | `seen`은 지금까지 저장한 상품 링크를 모아 두는 상자(집합)입니다. |
| 79 | 이번 페이지 상품 중 `seen`에 **없는** 것만 `new`에 남깁니다. `it[4]`는 상품 정보 묶음의 5번째 값, 즉 **상품 링크**입니다(0부터 셈). |
| 81~82 | `new`가 비었으면(상품이 없거나 전부 이미 본 상품) 반복을 멈춥니다(`break`). **이것이 종료 조건입니다.** 예전에는 페이지 수를 숫자로 고정했습니다. |
| 96~97 | 하나도 못 모았으면 오류로 끝내고, 기존 CSV는 그대로 둡니다. |
| 98 | 끝까지 왔을 때만 임시 파일을 진짜 CSV 자리로 옮깁니다(`os.replace`). 중간에 실패하면 이 줄까지 오지 않으니 **기존 CSV가 망가지지 않습니다.** |

**안전장치**: 24줄 `HARD_LIMIT = 150`. 종료 조건이 혹시 안 먹어도 150페이지에서는 멈춥니다(실제 마지막은 88페이지).

### ② 이로이로도쿄: 요청 주소와 도착 주소 비교 (`crawl_iroiro.py` 103~105줄)

**이 코드가 하는 일**: 요청한 주소와 실제 도착한 주소가 다르면(리다이렉트) 그 분류는 끝났다고 보고 멈춘다.

```python
97   url = ROOT + slug + "/" + ("" if page == 1 else f"page/{page}/")
98   res = get_with_retry(url, headers=HDR, timeout=30)
...
102  # 마지막 페이지를 넘기면 404가 아니라 메인 페이지로 리다이렉트된다. 주소가 바뀌었으면 끝난 것이다.
103  if unquote(res.url).rstrip("/") != unquote(url).rstrip("/"):
104      print(cat_name, f"{page}페이지부터 리다이렉트 -> 카테고리 끝", flush=True)
105      break
```

| 줄 | 뜻 |
|---|---|
| 97 | 요청할 주소를 만듭니다. 1페이지는 `.../분류/`, 2페이지부터는 `.../분류/page/2/` |
| 103 | `url`은 **요청한** 주소, `res.url`은 리다이렉트를 따라간 뒤 **도착한** 주소입니다. 둘이 다르면 다른 곳으로 보내진 것입니다. |
| 103 | `unquote`: 주소 안의 한글은 `%EC%8B%9D...`처럼 바뀌어 있어서, 비교 전에 원래 글자로 되돌립니다. |
| 103 | `rstrip("/")`: 끝의 `/` 유무 때문에 같은 주소가 다르게 보이지 않도록 끝 `/`를 지웁니다. |
| 104~105 | 몇 페이지에서 끝났는지 기록하고 멈춥니다. |

- requests는 리다이렉트를 **자동으로 따라가고**, 최종 응답의 상태코드는 200입니다. 그래서 상태코드로는 알 수 없었고, 주소를 비교해야 했습니다.

### ③ GitHub Actions의 코코재팬 403 (`check_robots.py` 47~51줄)

슬라이드 오른쪽 아래 검은 사진은 코드가 아니라 **GitHub Actions 실행 기록(로그)** 입니다. 그 기록을 남긴 코드가 이것입니다.

```python
47  else:
48      print(f"[확인 실패] {label}: robots.txt 응답코드 {res.status_code}")
49      # 차단 원인 확인용 기록: 서버 종류, Cloudflare 요청 번호, 응답 본문 앞부분
50      print("  server:", res.headers.get("Server"), "| cf-ray:", res.headers.get("CF-RAY"), "| cf-mitigated:", res.headers.get("cf-mitigated"))
51      print("  본문:", " ".join(res.text.split())[:300])
```

| 로그 줄 | 뜻 |
|---|---|
| `robots.txt 응답코드 403` | 접근 거부 |
| `server: cloudflare` | 응답을 보낸 것이 쇼핑몰 서버가 아니라 Cloudflare(앞단 보안 서비스) |
| `cf-mitigated: challenge` | Cloudflare가 "자동화 같아서 확인 절차로 막았다"는 표시 |
| `본문: ...<title>Just a moment...</title>` | 상품 페이지 대신 온 확인 페이지 |
| `Warning: 코코재팬은 ... 건너뜁니다` | `weekly-crawl.yml` 28~34줄이 남긴 경고. 코코재팬만 건너뛰고 저장소의 기존 CSV를 씀 |

### 문법 메모
- **집합 `set()`**: 중복 없이 값을 모으는 상자. `x in seen`으로 "이미 있나?"를 빠르게 확인합니다.
- **`with open(...) as f:`**: 파일을 열고, 블록이 끝나면 자동으로 닫습니다.
- **`break`**: 지금 돌고 있는 반복(while/for)을 즉시 빠져나옵니다.
- **f-string** `f"{page}페이지"`: 문자열 안에 변수 값을 끼워 넣습니다.

## 9장 정제와 분류

### ① 가장 뒤에 나온 키워드 우선 (`okashieri/categorize.py` 117~122줄)

**이 코드가 하는 일**: 모든 분류의 모든 키워드를 상품명에서 찾아 보고, **가장 뒤쪽에서 발견된 키워드**의 분류를 고른다.

```python
117  best_cat, best_pos = None, -1
118  for cat, words in RULES:
119      for w in words:
120          pos = text.rfind(w)
121          if pos > best_pos:
122              best_cat, best_pos = cat, pos
```

| 줄 | 뜻 |
|---|---|
| 117 | 지금까지 고른 분류(`best_cat`)는 없음, 그 위치(`best_pos`)는 -1로 시작합니다. |
| 118 | `RULES`(6~44줄)는 `("초콜릿", ["초콜릿", "초코", "킷캣", ...])` 같은 묶음 10개입니다. 분류 하나씩 꺼냅니다. |
| 119 | 그 분류의 키워드를 하나씩 꺼냅니다. |
| 120 | `rfind`: 상품명(`text`)에서 키워드를 **뒤에서부터** 찾아 그 위치(몇 번째 글자인지)를 줍니다. 없으면 -1. |
| 121~122 | 지금까지 찾은 것보다 **더 뒤**에 있으면 이 분류로 바꿉니다. |

**예시**: "초콜릿 커버 비스킷" → 공백을 지운 `초콜릿커버비스킷`에서
- "초콜릿"은 0번째 (초콜릿 분류)
- "비스킷"은 5번째 (쿠키·디저트 분류)
- 5가 더 크니까 **쿠키·디저트**

**앞뒤 흐름**
- 116줄 `text = clean(name)`: 찾기 전에 "녹차맛" 같은 **맛 표현을 지웁니다**. 안 지우면 "킷캣 녹차맛"이 음료(녹차)로 분류됩니다.
- 114~115줄: 직접 확인해서 정한 예외 목록(`MANUAL`)에 있으면 규칙보다 먼저 그걸 씁니다.
- 123~127줄: 키워드가 하나도 없으면 "과자" 단어 → 쇼핑몰 원래 분류 → 쇼핑몰별 기본값 → "기타" 순서로 정합니다.

### ② 가격 문자열을 정수로 (`okashieri/build_db.py` 54~56줄)

**이 코드가 하는 일**: '1,900원'에서 숫자가 아닌 글자를 모두 지우고 정수 1900으로 바꾼다.

```python
54  def parse_price(text):
55      digits = re.sub(r'[^\d]', '', text or '')
56      return int(digits) if digits else None
```

| 줄 | 뜻 |
|---|---|
| 55 | `re.sub(패턴, 바꿀 글자, 원본)`: 원본에서 패턴에 맞는 부분을 바꿉니다. `[^\d]`는 "숫자(`\d`)가 **아닌**(`^`) 글자 하나". 그걸 빈 글자 `''`로 바꾸니 **숫자만 남습니다.** `'1,900원'` → `'1900'` |
| 55 | `text or ''`: 값이 비어 있으면(None) 빈 글자로 바꿔 오류를 막습니다. |
| 56 | 숫자가 남았으면 `int`로 정수 변환, 아무것도 안 남았으면(`'NoDiscount'` 같은 경우) `None`(값 없음). |

**앞뒤 흐름** (126~137줄): 정가가 없으면 할인가와 같게 맞추고, 할인율을 계산합니다.
```python
126  sale = parse_price(row["할인가"])
127  orig = parse_price(row["정가"])
128  if sale is None: sale = orig
130  if orig is None: orig = sale
137  pct = round((orig - sale) / orig * 100)
```

### ③ 중복 차단 UNIQUE(site, url) (`build_db.py` 102줄)

```python
102  UNIQUE(site, url)
```
- 표를 만들 때 "쇼핑몰(site)과 상품 주소(url) 조합은 한 번만"이라는 규칙을 걸었습니다.
- 실제로는 그 전에 코드(120~124줄)가 `seen` 집합으로 같은 주소를 먼저 거르고, UNIQUE는 **혹시 빠져나간 중복을 DB가 거부하는 마지막 안전장치**입니다.
- 엔핍은 주소 뒤에 페이지 번호 같은 값이 붙어서, 상품 번호(`it_id`)만 남긴 주소로 통일한 뒤 비교합니다(59~64줄 `canon_url`).

**질문이 나오면**
- **UNIQUE에 실제로 걸린 적이 있나요?** 코드가 먼저 걸러서 UNIQUE까지 가는 중복은 없습니다. 코드에 실수가 생겨도 DB에 중복이 들어가지 않게 둔 장치입니다.

### ① INSERT에서 값은 ?로 전달 (`build_db.py` 139~144줄)

```python
139  conn.execute(

141      "VALUES (?,?,?,?,?,?,?,?,?,?,?,?)",
```

| 줄 | 뜻 |
|---|---|
| 140 | "products 표에 이 12개 칸으로 한 줄 넣어라" |
| 141 | 값 자리를 물음표 12개로 비워 둡니다. |
| 142~143 | 실제 값 12개는 **따로** 넘깁니다. 순서대로 물음표에 들어갑니다. |
| 143 | 마지막 두 값: `normalize(name)`는 공백을 지우고 소문자로 바꾼 이름(검색용), `normalize(to_initials(name))`는 **초성**(예: 고양이젤리 → ㄱㅇㅇㅈㄹ). **저장할 때 한 번 계산해 두는 부분이 여기입니다.** |

`to_initials`(42~47줄)는 한글 글자 번호에서 초성을 계산합니다. 한글 글자는 '가'부터 순서대로 번호가 매겨져 있고, 초성 하나마다 588글자씩 묶여 있어서 `(글자 번호 - '가' 번호) // 588`이 초성 순번이 됩니다.

### ② 초성 칼럼 검색 (`app.py` 52~54줄)

```python
49  for token in query.split():
50      token = token.lower()
52      column = "name_cho" if all(ch in CHO for ch in token) else "name_norm"
53      clauses.append(f"{column} LIKE ? ESCAPE '\\'")
54      params.append(f"%{like_escape(token)}%")
```

| 줄 | 뜻 |
|---|---|
| 49 | 검색어를 띄어쓰기로 나눠 단어(`token`)마다 처리합니다. "ㅋㅋ 초코"처럼 섞어 써도 됩니다. |
| 52 | 단어의 **모든 글자가 자음**(`CHO`, 12줄)이면 초성 칼럼(`name_cho`), 아니면 이름 칼럼(`name_norm`)에서 찾습니다. |
| 53 | 조건 문장에는 **칸 이름과 `?`만** 들어갑니다. 칸 이름은 위 두 개 중 하나라서 사용자가 바꿀 수 없습니다. |
| 54 | 실제 검색어는 `params`에 **따로** 담습니다. 앞뒤 `%`는 "앞뒤에 무엇이 있어도 됨"(포함 검색). |
| 54 | `like_escape`(32~33줄): 검색어에 `%`나 `_`가 있으면 LIKE의 특수 기호로 해석되지 않게 막습니다. |

### ③ 읽기 전용 연결 (`app.py` 27줄)

```python
27  conn = sqlite3.connect(f"file:{DB_PATH}?mode=ro", uri=True)
```
- `mode=ro`(read-only): 이 연결로는 DB를 **읽기만** 할 수 있습니다. 웹 요청 때문에 데이터가 바뀌거나 지워질 수 없습니다.
- `uri=True`: 앞의 `file:...?mode=ro`를 옵션이 붙은 주소로 해석하라는 뜻입니다.

### ④ 정렬은 허용 목록에서만 (`app.py` 141줄)

```python

17      "price_asc": "sale_price ASC",
18      "price_desc": "sale_price DESC",
19      "name": "name ASC",
20  }
...
141 order_by = SORTS.get(sort, SORTS["discount"])
```

| 줄 | 뜻 |
|---|---|
| 15~20 | 정렬 이름 → 실제 SQL 정렬 문장을 미리 정해 둔 사전(허용 목록) |
| 141 | 사용자가 보낸 `sort` 값으로 사전에서 꺼냅니다. **목록에 없는 값이면 기본값(할인율순)** 을 씁니다. |

- 정렬 문장은 150줄에서 쿼리에 **직접** 들어갑니다(`ORDER BY {order_by}`). `?`를 쓸 수 없는 자리라서, 들어갈 수 있는 글자를 이 4개로 제한한 것입니다.

**전체 조회 (145~152줄)**: 위에서 만든 조건(`where`)·값(`params`)·정렬(`order_by`)이 합쳐집니다.
```python

151      params + [PAGE_SIZE, (page - 1) * PAGE_SIZE],

```
- `where`: `name_norm LIKE ? AND sale_price <= ?` 같은 조건 문장 (값은 전부 `?`)
- `LIMIT ? OFFSET ?`: 40개씩, (페이지-1)×40번째부터. 3페이지면 80번째부터 40개

### 문법 메모
- **`all(조건 for ch in token)`**: token의 **모든** 글자가 조건을 만족하면 True
- **사전 `.get(키, 기본값)`**: 키가 없으면 오류 대신 기본값을 줍니다.
