# 오카시에리 — 선택과 이유

포트폴리오 발표용 기록. "무엇을 했는가"보다 "왜 그렇게 골랐는가"를 남긴다.

이름: 오카시(과자)와 오카에리(어서 와)를 합친 말. "과자야 어서 와".

## 문제 정의
일본 과자 직구 쇼핑몰이 여러 곳이라, 같은 과자를 사려면 사이트마다 들어가 가격을 비교해야 한다.
→ 여러 쇼핑몰 가격을 한 번에 검색하고, 사용자가 원하는 쇼핑몰의 상품 페이지로 바로 넘어가게 해주는 사이트. 최저가만 골라주는 게 아니라 비교한 뒤 선택은 사용자가 한다.

## 크롤링 가능 여부와 방식을 정한 기준
사이트마다 코드를 짜기 전에 같은 순서로 확인했다. 먼저 확인하면 헛수고를 줄이고 도구를 맞게 고를 수 있다.

1. **접근 가능한가**: 브라우저처럼 헤더를 붙여 요청하고 상태코드를 본다. 200이면 통과, IMDb는 202가 와서 봇 차단으로 판단해 제외했다.
2. **정적인가 동적인가**: 요청으로 받은 원본 HTML에 상품 이름이나 가격이 들어 있는지 본다(`'클래스명' in res.text`, 또는 가격 패턴 개수 세기). 있으면 정적, 없으면 동적이다. 개발자도구에서는 보이는데 원본 HTML에 없으면 자바스크립트가 나중에 그린 화면이라는 뜻이다.
3. **페이지는 어떻게 넘어가나**: 주소에 `page=2` 같은 번호가 있는지, 아니면 "더보기"가 주소 변화 없이 데이터를 따로 불러오는지(AJAX) 본다. 후자는 개발자도구 네트워크 탭에서 실제 요청 주소를 찾는다.

| 사이트 | 판단 | 사용한 방식 | 근거 |
|---|---|---|---|
| 코코재팬 | 정적 | `requests` + `BeautifulSoup`. 더보기는 AJAX 주소를 직접 호출 | 원본 HTML에 상품 클래스가 있었다. 더보기 요청은 HTML 조각을 돌려줘서 같은 파서로 처리했다. |
| 재팬푸드몰 | 정적 | `requests` + `BeautifulSoup`, 카테고리 코드와 `page` 번호 반복 | 원본 HTML에 가격이 492개 들어 있었다. 다만 robots.txt가 전체 금지라 이후 서비스에서 제외했다(아래 확인 결과 참고). |
| 엔핍 | **동적** | **Selenium**으로 렌더링 후 `page_source`를 파싱 | `requests` 결과에는 상품이 0개, Selenium에서는 20개였다. 렌더링 대기 시간을 줘야 한다. |
| 이로이로도쿄 | 정적 | `requests` + `BeautifulSoup`, `/page/N/` 반복 | 목록 페이지 HTML에 상품 80개와 원화 가격이 있었다. 이미지는 지연 로딩이라 `src`가 아닌 `data-src`를 읽었다. |
| 구루메상 | 정적 | `requests` + `BeautifulSoup` | 수집은 됐지만 품절, 더미, 스팸 게시물이 많은 사실상 운영 중단 사이트라 서비스에서 제외했다. |
| 코코마이 | 서버 렌더링(정적처럼 동작) | 보류 | 엔화 가격이라 환율과 배송비 기준을 먼저 정해야 한다. |

**왜 이 구분이 중요한가**: 정적 사이트에 Selenium을 쓰면 브라우저를 띄우느라 몇 배 느리고 무겁다. 동적 사이트에 `requests`를 쓰면 빈 데이터만 받는다. 그래서 먼저 판별하고 필요한 곳에만 Selenium을 썼다.

## robots.txt와 이용약관 확인
**순서 실수**: 크롤링을 모두 끝낸 뒤에 확인했다. 원래는 코드를 짜기 전에 `robots.txt`부터 봤어야 했다. 이후 새 사이트는 이 확인을 1단계(접근 가능 여부)에 넣는다.

**robots.txt** (사이트주소/robots.txt에 있는 크롤러 안내문. 법적 효력은 없지만 크롤링의 기본 예의)

| 쇼핑몰 | 결과 |
|---|---|
| 코코재팬, 엔핍, 이로이로도쿄 | 우리가 접근한 주소(목록, 상품, 이미지) 모두 허용 |
| 재팬푸드몰 | `User-agent: *` / `Disallow: /`로 일부 검색봇 외 크롤러를 전부 금지 |

**이용약관**: 네 곳 모두 크롤링이나 스크래핑을 직접 언급하지 않는다. 대신 정보 복제와 제공을 제한한다.
- 재팬푸드몰, 엔핍(제22조 ②): 사전 승낙 없이 몰의 정보를 복제, 송신, 배포해 **영리목적**으로 이용하거나 제3자에게 이용하게 하면 안 된다.
- 코코재팬, 이로이로도쿄(회원의 의무 4항 ①): 서비스로 얻은 정보를 사전 승낙 없이 복사, 복제, 변경, 출판 등으로 사용하거나 **타인에게 제공**하면 안 된다(영리목적 제한이 없다). 이 조항은 회원에게 적용되는 문구라 비회원에게 그대로 적용되는지는 판단하지 못했다.

**판단과 조치**
| 결정 | 이유 |
|---|---|
| 재팬푸드몰을 서비스(DB)에서 제외 | robots.txt가 명시적으로 금지했다. 약관을 보기 전에도 이것만으로 충분하다. 원본 수집 파일은 지우지 않고 로컬에만 남겼다. |
| 나머지 3곳은 로컬 시연과 화면 캡처 중심, 공개 배포는 허락 후 | 약관이 정보의 복제와 제공을 제한하므로, 인터넷에 공개하는 건 쇼핑몰의 허락을 받는 쪽이 안전하다. |
| 소개 페이지에 권리 안내, 광고와 제휴 링크 없음 | 상품명, 가격, 이미지의 권리는 쇼핑몰에 있고, 영리목적 제한 조항에 걸리지 않으려고 비영리 프로젝트임을 밝힌다. |

법적 판단이 아니라 약관과 robots.txt를 읽고 정한 보수적인 기준이다.

## 어떤 데이터를 어떻게 가져왔나
**가져온 데이터**: 제품명, 정가, 할인가, 이미지, 상품 링크, 카테고리(있는 사이트만). 비교와 구매 이동에 필요한 최소한만 모았다. 리뷰, 상세 설명처럼 쓰지 않을 데이터는 요청 수만 늘리므로 가져오지 않았다.

**위치를 찾는 방법(사이트마다 동일)**
1. 브라우저 개발자도구(F12)로 상품 하나를 검사해서, 상품 하나를 통째로 감싸는 **반복되는 태그**를 찾는다.
2. 그 안에서 이름, 가격, 이미지, 링크가 들어 있는 태그와 클래스를 찾는다.
3. `find_all`로 잡은 개수가 화면에 보이는 상품 수와 맞는지 확인한다. 안 맞으면 선택자가 너무 넓거나 좁은 것이다(구루메상은 범용 클래스가 메뉴까지 잡아서 171개가 나왔다).
4. 없을 수 있는 값(할인가 등)은 `None`인지 확인하고 기본값을 넣는다.

| 사이트 | 상품 단위 | 이름 | 정가 / 할인가 | 이미지 | 제외한 것 |
|---|---|---|---|---|---|
| 코코재팬 | `li.sct_li` | `div.sct_txt` | `span.coco2-was` / `span.coco2-now` | `img[src]` | BEST 캐러셀(`span.best_icon`) |
| 재팬푸드몰 | `li[style="width:25%;"]` | `strong.item_name` | `span.fixed-price` / `strong.item_price` | `img[src]` | 품절(`li.item_soldout`) |
| 엔핍 | `div.item-row` | `div.item-name b` | `span.original-price` / `span.sale-price` | `img[src]` (아래 참고) | - |
| 이로이로도쿄 | `div.type-product` | `p.name a` | `span.price` 안의 `del` / `ins` | `img[data-src]` | 품절(`outofstock`) |

**사이트마다 달랐던 함정과 대응**
- **엔핍 이미지**: 상품 카드 안의 첫 `<img>`가 상품 사진이 아니라 BEST 뱃지인 경우가 141개였다. 저장된 데이터를 눈으로 확인하다 발견했고, 상품 페이지의 대표 이미지(`og:image`)로 교체했다.
- **이로이로도쿄 이미지**: 지연 로딩이라 `src`는 빈 SVG이고 실제 주소는 `data-src`에 있다. `src`만 읽었다면 전부 빈 이미지였을 것이다.
- **링크**: 사이트마다 `href`가 상대경로(`../goods/...`)이거나 정렬 조건이 붙어 있어서, 절대 주소로 바꾸고 엔핍은 상품 ID만 남겨 정리했다. 같은 상품을 중복으로 거르는 기준이기도 하다.
- **가격 표기**: 사이트마다 할인이 없는 경우를 다르게 표현해서(`NoDiscount`, 정가만 표시 등), 저장 단계에서는 원문을 그대로 두고 DB로 옮길 때 숫자로 통일했다. 원문을 남겨 두면 변환이 틀려도 다시 계산할 수 있다.

## 수집 단계
| 선택 | 이유 |
|---|---|
| 정적 사이트는 `requests` + `BeautifulSoup` | 응답 HTML에 상품이 이미 들어 있으면 브라우저를 띄울 필요가 없어 빠르고 가볍다. |
| 동적 사이트(엔핍)만 Selenium | `requests`로는 상품 0개였다. JS가 그린 화면이 필요한 곳에만 무거운 도구를 쓴다. |
| 요청 사이 랜덤 딜레이, User-Agent 지정 | 대상 서버 부담을 줄이고 봇으로 오인되어 차단되는 것을 피한다. |
| 더미·품절·BEST 캐러셀 상품 필터링 | 가격 비교에 쓸 수 없는 데이터가 섞이면 결과 신뢰도가 떨어진다. |
| 크롤링은 하루 한 번 저장하는 배치 방식 | 사용자가 접속할 때마다 실시간으로 긁으면 느리고 쇼핑몰에 부담을 준다. |

## 데이터 정리 (`build_db.py`)
| 선택 | 이유 |
|---|---|
| 가격 문자열(`"3,500원"`)을 정수로 변환 | 문자열은 정렬이 틀린다(`"10,000"`이 `"9,000"`보다 앞에 온다). 비교와 정렬에는 숫자가 필요하다. |
| 할인 없는 상품은 정가 = 할인가로 통일 | 사이트마다 "할인 없음"을 다르게 표현해서, 화면과 정렬에서는 하나의 규칙으로 다루려고. |
| 같은 상품은 상품 ID 기준으로 중복 제거 | 재팬푸드몰은 신규상품이 다른 카테고리와 겹쳐 252건이 중복이었다. 같은 상품이 두 번 나오면 비교가 왜곡된다. |
| 중복 시 "신규상품" 카테고리는 뒤로 미룸 | 신규상품은 임시 분류라, 더 구체적인 카테고리 정보를 남기는 편이 검색과 분류에 유리하다. |
| 엔핍 이미지 141개를 상품 페이지의 대표 이미지(`og:image`)로 교체 | 목록에서 첫 `<img>`를 집었더니 BEST 뱃지 그림이 저장됐다. 데이터를 눈으로 확인하다 발견했고, 상품 링크로 올바른 사진을 다시 받았다. |
| 이미지 파일명을 `사이트_ID.jpg`로 저장 | 상품명으로 저장하면 특수문자(`*`, `/`)로 오류가 나고 이름이 겹치면 덮어써진다. |

## 저장소: SQLite
| 선택 | 이유 |
|---|---|
| SQLite | 서버 설치가 필요 없고 DB가 파일 하나라 배포가 쉽다. 상품 약 2천 개, 읽기 위주라 충분하다. |
| 한계 | 동시에 쓰는 사용자가 많아지면 PostgreSQL 같은 서버형 DB로 옮겨야 한다. |

## 검색
| 선택 | 이유 |
|---|---|
| 초성 칼럼을 미리 계산해 저장 | 검색할 때마다 계산하면 상품 수만큼 반복된다. 저장 시 한 번만 계산한다. |
| 단어 단위로 자음만이면 초성, 아니면 이름 검색 | `ㅋㅋ 초코`처럼 섞어 써도 동작한다. |
| 공백과 대소문자를 무시하는 정규화 칼럼 | "Kit kat"과 "kitkat"처럼 표기 차이로 검색이 빗나가는 것을 줄인다. |
| `LIKE` 검색어의 `%`, `_` 이스케이프 + 파라미터 바인딩 | 사용자 입력이 SQL이나 와일드카드로 해석되는 것을 막는다. |
| 정렬 기준은 허용 목록(딕셔너리)에서만 선택 | 정렬은 SQL 문자열에 들어가서 바인딩이 안 된다. 미리 정한 값만 쓰게 해서 SQL 주입을 막는다. |
| DB를 읽기 전용(`mode=ro`)으로 연다 | 웹 요청이 실수로 데이터를 바꾸지 못하게 한다. |

## 화면
| 선택 | 이유 |
|---|---|
| Flask | 화면과 서버 구조를 직접 설계해 볼 수 있고, 배포 단위가 단순하다. 데이터 도구(Streamlit)는 빠르지만 서비스 구조를 보여주기엔 부족하다. |
| 프론트는 순수 HTML/CSS/JS | 화면이 단순해서 빌드가 필요한 프레임워크는 과하다. |
| 크림 바탕에 붉은 포인트 | 일본 느낌을 내면서 할인율과 같은 계열이라 가격 사이트에 어울린다. 주황은 화면 전체가 한 색이라 답답했고, 초록은 녹차 상품과 겹쳐 더 초록이 됐다. 빨강으로 상단바와 배너를 채워 보기도 했지만 최종적으로 크림 바탕에 로고, 선택 표시, 버튼, 할인율만 빨강으로 두는 쪽을 골랐다. |
| UI는 빨강 하나와 중립색만 사용 | 카드에는 사진마다 색이 다르다. UI까지 여러 색을 쓰면 정신없어서 색을 줄였다. |
| 색을 CSS 변수 한곳에 모음 | 팔레트를 세 번 바꾸면서 곳곳에 박힌 색 때문에 번거로웠다. 변수로 모아 두면 색 변경이 숫자 몇 개 수정으로 끝난다. |
| 필터는 사이드바에만 두고, 900px 아래에서는 서랍으로 전환 | 데스크톱에서는 조건이 항상 보이는 사이드바가 빠르고, 좁은 화면에서는 목록이 우선이라 접는다. 상단 메뉴에 같은 필터(5천원 이하, 할인특가, 쇼핑몰, 카테고리)를 또 넣었다가 중복이라 뺐다. 같은 기능이 두 곳에 있으면 사용자가 어디를 써야 할지 헷갈린다. |
| 필터 상태를 주소(URL)에 저장 | 새로고침이나 링크 공유에도 검색 상태가 유지된다. |
| 목록은 "더보기"가 아니라 페이지 번호 | 상품이 2천 개가 넘어 68페이지인데, 더보기는 마지막 페이지에 가려면 수십 번 눌러야 한다. 번호 방식은 원하는 페이지로 바로 가고, 주소에 `page`가 남아 공유와 새로고침도 된다. 번호는 10개씩 묶어 보여주고(`‹ ›`는 묶음 단위 이동, `« »`는 맨 앞과 끝), 처음에 쓴 `1 2 3 … 68` 방식은 중간 번호로 이동하기 어려워 바꿨다. |
| 범위를 넘는 페이지는 서버가 마지막 페이지로 보정 | 주소를 직접 고치거나 필터를 바꿔 페이지 수가 줄어도 빈 화면이 나오지 않게 한다. |
| 입력 후 250ms 기다렸다 검색(디바운스) | 글자를 칠 때마다 서버를 부르면 낭비다. |
| 늦게 도착한 이전 응답은 버린다 | 빠르게 입력하면 옛 검색 결과가 새 결과를 덮어쓸 수 있다. |
| 카드는 `textContent`로 만든다 | 상품명에 HTML이 들어 있어도 실행되지 않게 한다(XSS 방지). |
| 외부 링크는 `rel="noopener noreferrer"` + 새 탭 | 쇼핑몰 페이지가 이 사이트를 조작하지 못하게 하고, 비교하던 화면을 유지한다. |

## 상품 분류 (`categorize.py`)
| 선택 | 이유 |
|---|---|
| 사이트마다 카테고리가 달라서 우리가 직접 10개 분류를 정의 | 코코재팬과 엔핍은 분류 정보가 아예 없고, 재팬푸드몰과 이로이로도쿄는 서로 이름이 다르다. 비교하려면 공통 기준이 필요하다. |
| 이름의 키워드로 분류하고, 이름에서 **가장 뒤에 나온 종류 단어**를 고른다 | 한국어 상품명은 종류가 끝에 오는 경우가 많다("초콜릿 커버 비스킷"은 비스킷). 첫 번째 키워드를 고르면 맛 표기에 속는다. |
| 종류 단어가 둘 이상이면 추가 분류(`sub_category`)도 붙인다 | "초코 쿠키"는 쿠키·디저트(대표)와 초콜릿(추가) 둘 다에서 검색된다. 추가 분류에는 초코·쿠키·땅콩·젤리처럼 그 자체로 상품 종류인 단어만 쓴다. 모든 키워드를 쓰면 1,401개 상품에 "가루비"→소스 같은 오분류가 붙어서 303개로 좁혔다. |
| "녹차맛", "간장 맛" 같은 맛 표현은 먼저 지운다 | "킷캣 녹차맛"을 음료로 분류하는 오류를 막는다. 맛은 종류가 아니라 향이다. |
| `맛밤`, `쇼콜라`는 지우기 전에 다른 단어로 바꾼다 | 맛 표현 제거가 "맛밤"을 지우고, "쇼콜라"의 "콜라"가 음료로 잡히는 부분 일치 오류를 막는다. |
| 쇼핑몰이 붙인 "/ 수입과자" 태그는 종류 키워드가 없을 때만 쓴다 | 이름 끝에 붙은 일반 태그가 실제 종류(쿠키, 모찌)를 덮어쓰는 것을 막는다. |
| 쇼핑몰 원래 분류는 마지막 보조로만 사용 | 이름만으로 안 풀릴 때만 참고한다. 사이트마다 기준이 달라 주된 근거로 쓰기엔 믿을 수 없다. |
| 결과를 확인하며 키워드를 고침 | 처음 "기타"가 214개(약 11%)였고, 목록을 직접 읽으며 규칙을 고쳐 25개(1% 안팎)로 줄였다. 완벽하진 않아서 틀리는 상품은 남는다. |
| 잘 안 맞는 건 "기타"로 둔다 | 억지로 분류하면 틀린 분류가 되어 검색 신뢰도가 떨어진다. |

## 일부러 하지 않은 것
- **같은 상품 묶기**: 사이트마다 상품명 표기가 달라 정확한 묶기가 어렵다. 틀리게 묶으면 잘못된 가격 비교가 나오므로, 30시간 일정에서는 제외하고 "가격순 정렬"로 쇼핑몰별 가격을 비교하게 했다.
- **용량당 가격**: 상품명에서 용량을 뽑는 규칙이 제각각이라 제외했다.
