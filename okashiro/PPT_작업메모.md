# 포트폴리오 PPT 작업 메모 (다른 PC·새 대화에서 이어서 수정할 때 읽을 것)

파일: `오카시에리_포트폴리오_v2.pptx` (14장). 이 문서는 PPT를 고칠 때 필요한 **방침·결정·남은 일**입니다.
슬라이드 전체 문구는 `ppt_원고_v2.js`에 있습니다. 프로젝트 내용 자체는 `공부자료/`와 `DECISIONS.md`를 보세요.

## 1. 성격
- **발표 자료가 아니라 포트폴리오**: 발표자가 없어도 읽고 이해되는 문서형. 슬라이드 노트(대본) 없음.
- 보여줄 것은 "고생한 과정"이 아니라 **내가 가진 역량과 생각(판단 근거, 고민한 흔적)**. 자랑·과장 표현 금지, 성과 수치 남발 금지.
- "다음 프로젝트에 적용할 점", "개선할 점" 항목은 **넣지 않음** (지수 지시). 마지막 장은 "범위와 한계"(사실만).

## 2. 교수님 피드백 (다른 발표자에 대한 것이지만 기준으로 삼음)
- 맨 앞에 이력서 형식 개요: 사진, 이름, 생년월일, 학력, 연락처, 이메일, GitHub, 경력/자격증 + 프로젝트명, 목적, 개발환경, 활용 도구, 예시 화면
- 핵심 메시지는 **기술 역량**
- 3단계 파이프라인: 수집 → DB화(검증·정제) → 서비스화
- 제목에 흐름이 드러나게, **명사형**으로 통일(서술형·구어체 금지), 용어 일관
- 이미지에는 캡션, 필요하면 박스
- 원인을 모르면 **"규명하지 못했다"** 라고 쓴다
- 저장과 호출 **쿼리(INSERT/SELECT)** 를 보여줄 것
- 기술 스택과 **어느 수준으로 사용했는지** 표기
- 시연 흐름은 일관된 순서

## 3. 지수의 디자인 취향
- 장식 최소화, 흰 배경·무채색. 남색(`1E3A5F`)은 제목 아래 선·소제목에만
- 글꼴 Pretendard, 슬라이드 번호 우측 하단
- 제목은 **짧은 명사구** (너무 길면 "투머치"라고 함)
- 목차 순서가 자연스러워야 함 (개요 → 배경과 목표 → 파이프라인·기술 스택 → 수집 → 검증·정제 → 저장·서비스 → 범위와 한계)
- 사실이 아닌 것, 확인하지 않은 것은 쓰지 않음 ("거짓정보 쓰지마")
- 새 파일을 계속 만들지 말고 가능하면 같은 파일을 수정

## 4. v2 구성 (14장)
1 표지 / 2 목차 / 3 개요(이력서형) / 4 배경과 목표 / 5 데이터 파이프라인 / 6 기술 스택 /
7 수집 방식 설계 / 8 수집 허용 범위 확인 / 9 수집 데이터의 검증과 수정 / 10 정제와 분류 /
11 저장과 조회 쿼리 / 12 서비스 화면 / 13 서비스 구성과 자동 수집 / 14 범위와 한계

장 틀: 한 줄 배경 → 표(판단 사항 / 검토한 대안 / 결정과 근거) → 한계·규명하지 못한 점.

## 5. 남은 일 (지수가 채울 것)
- 3장 개요: 사진, 이름, 생년월일, 학력, 연락처, 이메일, 주요 경력, 자격증 → 현재 `[입력]`
- 3장 "예시 화면" 칸에 시작 화면 캡처 삽입
- 12장 서비스 화면 캡처는 쇼핑몰 상품 이미지가 들어 있음 → **공개 배포 전에는 교체**
- "Claude Code: 코드 작성·수정 보조"를 기술 스택(6장)과 개요(3장)에 적어 둠 → 유지할지 지수가 결정
- 8장 "수집 대상 사이트 모두 200 응답"은 이전 크롤링 체크 결과 기준 (재확인하지 않음)
- 12장은 PowerPoint에서 캡처 3장이 겹치거나 잘리는지 눈으로 확인 필요 (계산상 경고만 있음)
