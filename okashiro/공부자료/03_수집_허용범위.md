# 03. 수집 허용 범위: robots.txt와 이용약관

## 1. 핵심 개념: "접속된다" ≠ "수집해도 된다"
- **상태코드 200**: 서버가 응답했다 = 기술적으로 접속 가능
- **robots.txt**: 사이트 운영자가 "크롤러는 이 경로에 오지 말라"고 적어 둔 안내문
- 둘은 별개입니다. 200이 나와도 robots.txt가 금지하면 수집 허용이 아닙니다.

처음에 접속 가능 여부만 확인했을 때는 모든 사이트가 통과했습니다. robots.txt를 읽고 나서야 재팬푸드몰이 걸렸습니다.

## 2. robots.txt 읽는 법
주소: `사이트주소/robots.txt` (예: `https://cocojpmall.com/robots.txt`)
```
User-agent: *        ← 모든 크롤러에게
Disallow: /          ← 사이트 전체 접근 금지
```
```
User-agent: *
Disallow: /admin/    ← /admin/ 아래만 금지, 나머지는 허용
```
- **법적 효력은 없는 관례**지만, 운영자의 의사 표시이므로 존중하는 것이 크롤링의 기본 예의입니다.
- 파이썬에는 읽는 도구가 있습니다: `urllib.robotparser.RobotFileParser` → `can_fetch(UA, 주소)`가 True/False.

## 3. `check_robots.py` 해설
수집하려는 주소들이 robots.txt에서 허용되는지 확인하는 스크립트입니다. 수집 전에 먼저 실행하고, 허용되지 않으면 수집을 중단합니다.

```python
res = requests.get(robots_url, timeout=20, headers={"User-Agent": "Mozilla/5.0"})
parser = rp.RobotFileParser()
if res.status_code == 200:
    parser.parse(res.text.splitlines())
elif res.status_code in (404, 410):
    parser.parse([])      # robots.txt가 없으면 제한이 없는 것으로 본다
else:
    print(f"[확인 실패] ...응답코드 {res.status_code}")
    bad += 1
    continue
for u in urls:
    ok = parser.can_fetch(UA, u)
    print(("[허용] " if ok else "[금지] ") + label, u)
```
- 200: 내용을 읽어 규칙으로 사용
- 404/410: robots.txt가 없음 = 제한 없음으로 처리 (관례)
- 그 외(403 등): **판단 불가** → 안전하게 "확인 실패"로 처리하고 수집하지 않음
- 확인하는 주소: 목록 페이지, AJAX 주소 등 **우리가 실제로 접근하는 주소**
- 쇼핑몰 이름을 인자로 주면 그 사이트만 확인합니다(`python check_robots.py 엔핍`). GitHub Actions에서 사이트별로 따로 호출하기 위함.
- 비정상 응답일 때 서버 종류·`cf-ray`·응답 본문 앞부분을 출력하도록 추가했습니다(차단 원인 확인용, 아래 6번).

## 4. 확인 결과
| 쇼핑몰 | robots.txt | 조치 |
|---|---|---|
| 코코재팬 | 우리가 접근한 주소 허용 | 서비스 사용 |
| 엔핍 | 허용 | 서비스 사용 |
| 이로이로도쿄 | 허용 | 서비스 사용 |
| 재팬푸드몰 | `User-agent: *` / `Disallow: /` (일부 검색봇 외 전면 금지) | **서비스 제외**, 원본 파일은 로컬에만 보관 |
| 구루메상 | (허용 여부와 별개로) 품절·더미·스팸이 많은 사실상 운영 중단 사이트 | 서비스 제외 |

## 5. 이용약관
네 곳 모두 크롤링·스크래핑을 직접 언급하지 않지만, **정보의 복제와 제공을 제한**하는 조항이 있습니다.
- 재팬푸드몰, 엔핍: 사전 승낙 없이 몰의 정보를 복제·송신·배포해 **영리 목적**으로 이용하는 것을 금지
- 코코재팬, 이로이로도쿄: 서비스로 얻은 정보를 사전 승낙 없이 복사·복제·변경·출판하거나 **타인에게 제공**하는 것을 금지

따라서 이 사이트를 **공개 배포하려면 쇼핑몰의 허락이 필요**하다고 판단했고, 현재는 로컬에서 시연하는 용도로 둡니다.
배려 조치: 요청 간 2~4초 지연, 일주일에 한 번만 수집.

## 6. 확인 순서
robots.txt 확인을 **수집을 모두 끝낸 뒤**에 했습니다. 원래는 코드를 쓰기 전에 가장 먼저 해야 합니다.
순서가 틀어져서 재팬푸드몰을 이미 수집(703건)한 뒤에 제외하게 됐습니다.
이후에는 새 사이트마다 ① 접근 가능한가 → ② robots.txt/약관 → ③ 정적/동적 → ④ 페이지 이동 방식 순으로 봅니다.

## 7. 코코재팬 robots.txt 403 (GitHub 서버에서만)
자동 수집을 GitHub Actions로 옮기자 코코재팬 robots.txt만 403이 났습니다.

확인한 것 (직접 시험):
- 제 PC에서는 User-Agent를 `Mozilla/5.0`, `python-requests`, 빈 값으로 바꿔도 모두 **200**
- 응답 헤더에 `Server: cloudflare`, `cf-ray` → 코코재팬은 **Cloudflare(보안·CDN 서비스) 뒤에** 있음
- 따라서 요청 내용(User-Agent)이 아니라 **요청이 나온 장소(GitHub 서버의 주소)** 때문일 가능성이 높음

확인 결과 (Actions 로그): `cf-mitigated: challenge`, 본문 `Just a moment...` → **Cloudflare의 봇 확인 챌린지**가 GitHub 서버 요청에 적용된 것.
robots.txt의 금지 규칙이 아니라 접속 단계에서 막힌 것입니다. GitHub 서버만 대상이 된 이유(서버 주소 평판 등)는 Cloudflare 내부 판단이라 확인하지 못했습니다.
챌린지를 통과시키는 우회는 하지 않고, 코코재팬만 PC에서 수집합니다.

대응: 코코재팬은 GitHub에서는 건너뛰고(워크플로의 `if python check_robots.py 코코재팬; then ... else (경고) fi`), PC에서 수집해 CSV를 저장소에 올립니다. 점검 과정 전체는 07번 문서 14절.
