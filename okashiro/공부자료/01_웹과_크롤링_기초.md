# 01. 웹과 크롤링 기초

## 1. 크롤링이란
사람이 브라우저로 쇼핑몰을 열어 상품을 보는 일을 **프로그램이 대신** 하는 것입니다.
프로그램이 사이트에 접속해서 페이지 내용(HTML)을 받아오고, 그 안에서 필요한 부분(상품명, 가격, 이미지 주소)만 뽑아 저장합니다.
(뽑아내는 단계를 따로 "스크래핑/파싱"이라고도 하지만, 이 프로젝트에서는 합쳐서 크롤링이라고 부릅니다.)

## 2. 브라우저가 페이지를 여는 과정 (요청과 응답)
1. 주소(URL)를 입력하면 브라우저가 서버에 **요청(request)** 을 보냅니다. 가장 흔한 요청이 GET("이 페이지 주세요")입니다.
2. 서버는 **응답(response)** 을 돌려줍니다. 응답에는 두 가지가 들어 있습니다.
   - **상태코드**: 결과가 어땠는지 숫자로 알려 줌
   - **본문(body)**: HTML 텍스트 (이미지라면 이미지 파일)
3. 브라우저는 HTML을 읽어 화면으로 그립니다.

크롤링은 3번(그리기) 없이 2번(받아오기)까지만 하고, 받은 HTML에서 데이터를 직접 꺼냅니다.

### 상태코드 (우리 프로젝트에서 실제로 마주친 것)
| 코드 | 뜻 | 우리 프로젝트에서 |
|---|---|---|
| 200 | 정상 | 접속 가능 여부 확인에 사용. 단, **200은 "수집해도 된다"는 뜻이 아님** |
| 403 | 접근 거부 | GitHub 서버에서 코코재팬 robots.txt가 403 (07번 문서) |
| 404 | 페이지 없음 | 보통 마지막 페이지 판단에 쓰지만, 이로이로도쿄는 404 대신 메인으로 이동시켜서 다른 방법이 필요했음 |

### User-Agent (요청 헤더)
요청에는 "나는 누구다"라는 정보(헤더)가 붙습니다. 그중 User-Agent는 브라우저 종류입니다.
파이썬 `requests`가 기본으로 보내는 값은 "python-requests"라서 봇으로 보이기 쉽습니다.
우리 코드는 `HDR = {'User-Agent': 'Mozilla/5.0 ...Chrome...'}`로 일반 브라우저 값을 지정했습니다.
(참고: 코코재팬 403은 User-Agent와 무관하다는 것을 PC에서 확인했습니다. 07번 문서.)

## 3. HTML 구조
HTML은 **태그의 트리**입니다. 상품 하나가 이런 식으로 들어 있습니다(엔핍 예시, 단순화).

```html
<div class="item-row">                         ← 상품 카드 하나
  <a href="/shop/item.php?it_id=1234">          ← 상품 링크
    <img src="https://.../a.jpg">              ← 이미지
    <div class="item-name"><b>카루비 감자칩</b></div>
    <span class="original-price">2,500원</span>
    <span class="sale-price">1,900원</span>
  </a>
</div>
```
- **태그**: `div`, `span`, `a`, `img`, `b`
- **class**: 태그에 붙은 이름표. 같은 종류 요소를 묶음. 크롤링에서는 "이 class를 가진 태그를 찾아라"로 요소를 지목합니다.
- **속성**: `href`(링크), `src`(이미지 주소)처럼 태그 안의 `이름="값"`.

사이트마다 class 이름이 다르기 때문에, **사이트마다 코드를 따로** 짜야 합니다. 개발자도구(F12)의 Elements 탭에서 직접 보고 정합니다.

## 4. 파싱: BeautifulSoup과 lxml
받은 HTML은 그냥 긴 문자열입니다. 이를 태그 트리로 해석하는 것이 **파싱**입니다.
- **BeautifulSoup**: "class가 item-row인 div를 모두 찾아줘" 같은 검색 기능을 주는 라이브러리
- **lxml**: BeautifulSoup 안에서 실제로 HTML을 해석하는 엔진(파서). 빠르고 깨진 HTML도 잘 처리합니다.
  `BeautifulSoup(res.text, "lxml")`의 `"lxml"`이 "이 엔진으로 해석해라"라는 뜻입니다.

자주 쓰는 동작(우리 코드에 모두 나옴):
```python
soup.find_all('div', attrs={'class': 'item-row'})   # 조건에 맞는 모든 태그 (리스트)
product.find('span', attrs={'class': 'sale-price'}) # 조건에 맞는 첫 태그 (없으면 None)
tag.get_text().strip()                              # 태그 안 글자, 앞뒤 공백 제거
tag.get('href')                                     # 속성값
card.select_one("p.name a")                         # CSS 선택자로 찾기 (이로이로도쿄에서 사용)
```
`find`는 못 찾으면 `None`을 돌려주므로 `if price else ...`처럼 확인하지 않으면 오류가 납니다.
우리 코드에서 할인이 없는 상품이 이 경우입니다(할인 태그 자체가 없음).

## 5. 정적 사이트와 동적 사이트
- **정적(서버 렌더링)**: 서버가 이미 상품이 들어간 완성된 HTML을 보냄. `requests`로 받으면 상품이 그대로 들어 있음.
- **동적(클라이언트 렌더링)**: 서버는 빈 틀만 보내고, 브라우저에서 **자바스크립트가 실행되며** 상품을 나중에 채움. `requests`로 받으면 상품이 없음(빈 데이터).

### 판별법 (우리가 실제로 쓴 방법)
```python
res = requests.get(url, headers=HDR)
print('item-row' in res.text)     # True면 정적, False면 동적
```
개발자도구에서는 보이는데 `res.text`에는 없다 → 자바스크립트가 나중에 그린 것 → 동적.

### 결과
| 사이트 | 판별 | 근거 |
|---|---|---|
| 코코재팬 | 정적 | 원본 HTML에 상품 클래스 존재 |
| 이로이로도쿄 | 정적 | 목록 HTML에 상품 80개 존재 |
| 엔핍 | **동적** | requests 결과 상품 0개, Selenium 결과 20개 |

### 도구 선택의 이유
- 정적에 Selenium을 쓰면: 실제 크롬을 띄우므로 몇 배 느리고 무거움 → 낭비
- 동적에 requests를 쓰면: 빈 데이터만 받음 → 실패
- 그래서 **정적은 requests + BeautifulSoup, 동적(엔핍)만 Selenium**.

## 6. Selenium
실제 크롬 브라우저를 코드로 조종하는 도구입니다. 페이지를 열면 자바스크립트가 실행되어 상품이 그려지고, 그 뒤의 HTML(`driver.page_source`)을 BeautifulSoup으로 파싱합니다.
- `--headless=new`: 화면 창 없이 실행 (서버에서 돌리려면 필수)
- `time.sleep(3)`: 자바스크립트가 그릴 시간을 기다림
- `webdriver_manager`: 크롬 버전에 맞는 드라이버(chromedriver)를 자동으로 내려받음

## 7. 페이지 이동 방식 3가지 (사이트마다 다름)
상품이 수천 개라 한 페이지에 다 있지 않습니다. 다음 페이지로 가는 방식이 사이트마다 다릅니다.
| 방식 | 모양 | 사이트 |
|---|---|---|
| URL 파라미터 | `...list.php?ca_id=s0&page=2` | 엔핍 |
| 경로형 | `.../쿠키-스낵-과자/page/2/` | 이로이로도쿄 |
| AJAX("더보기") | 주소는 그대로인데 버튼을 누르면 내부 주소로 데이터를 따로 받아옴: `list_more_ajax.php?...&page=2` | 코코재팬 |

### AJAX를 찾는 방법
개발자도구 → Network 탭 → "더보기" 클릭 → 새로 생긴 요청의 주소를 확인.
그 주소를 `requests`로 직접 부르면 됩니다. 코코재팬의 응답은 HTML 조각이라 같은 파서로 처리할 수 있었습니다.

## 8. 마지막 페이지를 아는 법 (종료 조건)
처음에는 "코코재팬은 8페이지"처럼 **페이지 수를 고정**했다가 192건만 수집했습니다. 실제는 88페이지였습니다.
그래서 고정 대신 **종료 조건**을 씁니다.
- 상품이 하나도 없는 페이지가 나오면 종료
- 이미 본 상품만 나오면 종료 (`seen` 집합과 비교)
- 응답 주소가 요청한 주소와 다르면 종료 (이로이로도쿄: 마지막 페이지 뒤에 메인으로 이동시킴)
- `HARD_LIMIT = 150`: 위 조건이 모두 실패해도 무한 루프가 되지 않게 하는 안전장치

## 9. 이미지 지연 로딩 (lazy loading)
이미지가 화면에 보일 때 비로소 로드되도록 `src`에는 빈 이미지를 두고 진짜 주소를 `data-src`에 넣는 사이트가 있습니다.
이로이로도쿄가 그렇습니다. `src`만 읽으면 전부 빈 이미지가 됩니다.
```python
imgurl = (img.get("data-src") or img.get("src")) if img else None
```

## 10. 파일 저장 시 주의
- 상품명에 `* / : ? " < > |` 같은 글자가 있으면 윈도우에서 파일 저장 오류가 납니다 → `safe_filename()`이 `_`로 바꿈
- 상품명 앞뒤 공백·줄바꿈 → `.strip()`
- 한글 CSV는 `encoding="utf-8-sig"`로 저장해야 엑셀에서 깨지지 않음(BOM)
