## 2. 남은 할 일 (`최종.pptx` 기준)

1. **3·4장 합치기** (합치는 것으로 결론). 합친 3장 구성안:
   - 프로젝트명 / 문제 / 목표 / 핵심 역량 / 개발환경 / 기술 스택 / 활용 도구 / GitHub, 오른쪽에 예시 화면
   - 문제: 쇼핑몰별 가격·표기·분류 기준 차이 → 최저가 확인을 위한 사이트별 개별 검색 반복
   - 목표: 여러 쇼핑몰 상품의 통합 검색과 가격순 비교
2. **3장 인적사항** 추가 (사진, 이름, 생년월일, 학력, 연락처, 이메일, GitHub, 주요 경력, 자격증). `최종6` 3장에 틀이 있음
3. **1장 부제**: "직구 … 웹사이트" → "일본 과자 대행구매 쇼핑몰 가격 비교 서비스"
4. **배운 점 장** 추가 (`최종6` 12장): 겪은 일 → 배운 점 → 다음 프로젝트 적용, 3행
5. **용어 정리** 교체 (`최종6` 13~15장, 용어마다 2~3줄 설명)
6. **6장 '선택 이유'** 대체어 결정 (추천: "판단 근거", 다른 후보: "선택 근거")
7. **7장 F12 캡처**: 개발자도구에서 상품 카드 태그·클래스에 빨간 박스
8. 목차를 최종 장 구성에 맞게 수정
9. 대본을 최종 슬라이드에 맞게 정리 (3·4장 합치면 대본도 합치기)

## 3. 정해진 원칙 (지수 지시 + 선생님 피드백)

- 발표자료가 아니라 **포트폴리오**: 역량이 드러나게. "어떤 문제 → 어떤 지식 → 그래서 이렇게 함"
- 슬라이드 문장은 **명사형**. 구어체("~해서", "받아", "보니") 금지
- 단답 요약 금지. "서버 불필요" 같은 조각 대신 이유가 드러나게
- **'한계' 줄은 슬라이드에서 삭제**. 의미 있는 것은 배운 점 장으로만
- 6장 "AI 활용" 줄은 삭제 (Claude Code는 3장 활용 도구에만)
- 사진·코드 캡처 아래에는 "무엇을 위한 코드인지" 캡션
- 용어는 통일 (DB/저장소 혼용 금지, '대행구매'로 통일)
- 큰 제목만 읽어도 흐름이 보이게

## 5. 확인된 사실 (질문 대비)

- 엔핍 정적·동적 판별: 수집 당시 requests 0개 / Selenium 20개 → 동적. 2026-10 재확인 때는 requests도 20개 (이유 규명 못 함)
- robots.txt: `check_robots.py`가 GitHub Actions 워크플로에서 사이트별 수집 직전에 실행, 비허용이면 `exit 1`로 수집 중단
- 예약 수집: cron `0 18 * * 6` = 한국 시간 일요일 새벽 3시
- 코코재팬은 GitHub Actions에서 Cloudflare 챌린지(403) → PC 수집 CSV 사용
- 이름 표기: お菓子 + おかえり 대신 "오카시(과자)와 오카에리(어서 와)를 합친 말", 시작 화면은 `おかしえり`
